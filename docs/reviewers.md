# 👥 Reviewers Guide

# Revisores da Cs-Brazil

Os revisores são responsáveis por ajudar a manter a qualidade técnica e didática da comunidade.

O objetivo da revisão não é encontrar erros para rejeitar contribuições.

O objetivo é ajudar cada colaborador a produzir um material melhor.

Uma boa revisão beneficia três pessoas:

* quem escreveu;
* quem revisou;
* quem estudará aquele conteúdo no futuro.

---

# 🎯 Responsabilidades

Um revisor deve procurar responder às seguintes perguntas:

## 📚 O conteúdo está correto?

Verifique se:

* os conceitos técnicos estão corretos;
* as informações estão atualizadas;
* exemplos de código fazem sentido;
* não existem erros conceituais.

---

## ✍️ A explicação está clara?

Pergunte-se:

* Um iniciante entenderia esta explicação?
* Existem saltos de raciocínio?
* Há termos técnicos sem explicação?
* Uma analogia poderia facilitar o entendimento?

Lembre-se:

Um conteúdo tecnicamente correto ainda pode ser difícil de entender.

---

## 💻 Os exemplos funcionam?

Sempre que possível:

* execute os exemplos;
* valide comandos;
* verifique saídas esperadas;
* confirme que instruções podem ser reproduzidas.

Evite aprovar exemplos que nunca foram testados.

---

## 📖 O conteúdo segue a metodologia?

Verifique se o material contém, quando aplicável:

* explicações autorais;
* exemplos próprios;
* exercícios;
* Diário de Estudo;
* diagramas próprios;
* referências.

---

# 💬 Como revisar um Pull Request

Durante uma revisão:

✅ Explique o motivo da sugestão.

✅ Mostre alternativas.

✅ Compartilhe referências quando possível.

✅ Seja respeitoso.

Evite comentários vagos como:

> "Isso está errado."

Prefira:

> "Acredito que este exemplo possa gerar confusão porque o comando se comporta de forma diferente em distribuições baseadas em Debian. Talvez possamos incluir essa observação."

Uma boa revisão também ensina.

---

# ❤️ Assuma boa intenção

A maioria das pessoas está contribuindo para aprender.

Erros fazem parte desse processo.

Ao revisar:

* corrija o conteúdo;
* incentive o autor;
* explique o motivo das mudanças.

Nossa meta é formar novos colaboradores, não afastá-los.

---

# 🚨 Quando solicitar alterações

Solicite mudanças quando houver:

* erros conceituais;
* exemplos incorretos;
* conteúdo superficial;
* organização confusa;
* problemas de direitos autorais;
* imagens protegidas;
* texto claramente não revisado.

Sempre explique o motivo da solicitação.

---

# ✅ Quando aprovar

A aprovação não significa que o conteúdo é perfeito.

Significa que:

* está tecnicamente correto;
* está suficientemente claro;
* segue as diretrizes da comunidade;
* pode ser publicado.

Pequenos ajustes podem acontecer em Pull Requests futuros.

---

# 🤖 Conteúdo produzido com IA

O uso de IA é permitido.

Entretanto, o revisor deve verificar se:

* o autor compreendeu o assunto;
* o conteúdo faz sentido;
* não existem informações inventadas;
* os exemplos funcionam;
* o texto não está excessivamente genérico.

A responsabilidade final continua sendo humana.

---

# 📚 Especialidades

Ninguém domina todas as áreas da computação.

Por isso incentivamos revisores especializados.

Exemplos:

* Sistemas Operacionais
* Linux
* Redes
* Compiladores
* Banco de Dados
* Rust
* Go
* C
* C++
* Java
* Python
* Kubernetes
* Docker
* Arquitetura de Software
* Sistemas Distribuídos
* Segurança

Sempre que possível, um Pull Request deve ser revisado por alguém com experiência no assunto.

---

# 🙋 Como se tornar um revisor

Caso queira ajudar revisando conteúdo:

1. Abra uma Issue no repositório principal.

2. Utilize o título:

```text id="vdb7l8"
[REVISOR] Nome - Especialidade
```

Exemplo:

```text id="qpkm2f"
[REVISOR] Ana - Rust / Sistemas Distribuídos
```

3. Informe:

* tecnologias que domina;
* experiência profissional ou acadêmica (quando desejar compartilhar);
* assuntos nos quais gostaria de revisar contribuições.

Os mantenedores poderão convidá-lo para participar das revisões relacionadas à sua área.

---

# 🌱 Crescendo juntos

Uma revisão não é apenas uma aprovação.

Ela é uma oportunidade de ensinar.

Se cada Pull Request terminar com o autor sabendo mais do que quando começou, a comunidade inteira evolui.

Nosso objetivo não é apenas produzir conteúdo de qualidade.

É formar pessoas capazes de ensinar outras pessoas.

Essa é a essência da Cs-Brazil.
